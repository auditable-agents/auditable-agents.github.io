Auditable Agents

An accountability layer for agents that act

When an agent takes a consequential action and the outcome is wrong, three questions usually have no good answer: what did it rely on, could that have been checked first, and can the action be undone. This is an open-source ecosystem for answering all three.

Before deployment

Detect

Scan agent code and configurations for risks that would only surface at run time. agent-audit

At execution

Enforce

Gate a tool call before it commits, and write a tamper-evident record of the decision. Aegis

After the commit

Recover

Replay a decision against current state and roll the action back when its basis no longer holds. auditable

01 / Components

One layer, four tools, one framework

Each tool is useful on its own. Together they cover an agent action end to end, which is why they are maintained as one ecosystem rather than four unrelated repositories.

03 / Governance

Where this ecosystem actually stands

Publishing an accurate account of the current state matters more than a polished one, particularly for tooling whose job is to make other systems inspectable.

Today

  • Each repository is effectively maintained by one developer. No component yet has a second regular committer.
  • The components sit under four different licenses and were developed in separate personal accounts.
  • There is no shared release process, no cross-component interface contract, and no published governance model.
  • A tool that audits other systems should carry the strongest integrity guarantees of anything it inspects. That standard is not met yet.

What this organization is for

  • Hold the components under one umbrella so the ecosystem has an identity that does not depend on any individual maintainer's personal or commercial pages.
  • Publish a component manifest and at least one working cross-component interface, so a finding, a policy decision, and a recovery record can refer to the same action.
  • Publish a governance model covering maintainer appointment, succession, release authority, and conflict handling, plus a security policy with coordinated disclosure.
  • Grow a contributor base beyond a single maintainer per repository, which is the main thing standing between this and a sustainable ecosystem.
04 / Taking part

Contributing and reporting

Contribute

Each repository takes issues and pull requests directly. Good starting points are new detection rules for agent-audit, policy examples for Aegis, and additions to awesome-auditable-ai.

Report a vulnerability

Please do not open a public issue for a security problem. Report it privately through the relevant repository's GitHub security advisory page, and expect an acknowledgement while a fix and coordinated disclosure are arranged.

Publish an Auditability Card

The Auditability Card is a disclosure format for stating which accountability guarantees a system provides. The format is described in the framework paper. If you publish one for your own system, open an issue so it can be listed.

Open source

An independent open-source ecosystem for AI agent accountability. Maintained by its contributors; not affiliated with, and not speaking for, any company.
